# Security & privacy (current state)

Implemented and tested: scrypt password hashing (N=2¹⁵); JWT access (15 min) + opaque refresh tokens stored only as SHA-256, rotated on use, **reuse revokes the whole family**; constant-ish-time login (dummy hash for unknown users); role checks (`require_role`); per-IP auth rate limiting (in-process); strict Pydantic validation (handles, slugs, sizes); upload size cap (2 MB) and row validation; per-user data isolation on profiles/sheets/challenges (foreign IDs return 404); audit log; data export and account deletion; production refuses the default JWT secret; no secrets in code (env, `CODEMIND_*`); external content treated as data (metadata and links only; sheet text is escaped by React).
**Known gaps**: tokens in `localStorage` (XSS-exposed) → move to httpOnly cookies; no encryption-at-rest config (deployment concern); no consent UI for telemetry beyond the optional `minutes` field; no sandbox yet (**code execution is not implemented, so no user code runs anywhere**); LLM prompt-injection defences not applicable until the mentor exists; no dependency/vuln scanning in CI.


## Added in this round
Sandbox isolation (see CODE_EXECUTION.md) with 13 adversarial tests; LLM prompts treat retrieved/user text as data and strip instruction-like lines; output validators remove unverified URLs and withhold code per hint level; provider keys are server-side env vars and are never returned by any endpoint (tested); consent-gated training capture stores no user id; leaderboard and sharing are opt-in; community has rate limits, duplicate/link-spam checks, reports, mutes and role-gated moderation with audit log entries; WebSocket requires a valid access token. **Still open:** tokens in `localStorage`, no CSP/headers, per-process rate limiter, executor shares a host with the API in dev, no dependency scanning.

## Added in the "build all this" round
Implemented and tested: email verification + password reset (single-use, SHA-256-stored, expiring tokens; identical response whether or not the email exists; reset revokes every session); TOTP MFA (own RFC 6238 implementation, replay-protected, password required to disable; login returns `mfa_required` before any token is issued); Redis-backed rate limiter (fail-open, verified against a real Redis; per-process fallback); Prometheus metrics (optional bearer token) + JSON request logs with request ids; remote executor service with shared-key auth; Next.js response headers (CSP, X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy), checked in a real browser: 3D canvases, Monaco and React Flow still load with no CSP violations.
**Honest limits:** the CSP is *partial*: `script-src` still needs `'unsafe-inline'`/`'unsafe-eval'` (Next.js bootstrap + Monaco loader from cdn.jsdelivr.net), so it does not stop injected inline scripts; tokens are still in `localStorage`; emails are only sent if SMTP is configured (otherwise the link is logged server-side, never returned to the client); MFA has no recovery codes yet; no dependency/vulnerability scanning in CI; GitHub Actions workflow has never been run.

## Capture tokens (browser extension)
`nxc_` tokens are random 256-bit, stored only as SHA-256, shown once, revocable, capped at 5 per user, rate-limited (30 uploads/min/token), and accepted ONLY by `POST /capture/submissions` (they are not user sessions; a user JWT is rejected there and a capture token is rejected everywhere else; tested). Uploaded rows are untrusted by design: provenance `extension`, excluded from Daily Challenge auto-verification. The extension never reads the code editor and uploads no source code.

## Delivery pipeline and runtime hardening (added with the distributed deployment)
CI now runs CodeQL (Python, JS/TS; automatic once the repository is public, or when code scanning is enabled and the repository variable `ENABLE_CODEQL=true` is set), a weekly `pip-audit`/`npm audit`, Dependabot, hadolint, and a Trivy scan of every image (fails on fixable CRITICAL findings); images are built with provenance and SBOM and attested in CD. `pip-audit`/`npm audit` have run on GitHub once (passed); the Trivy image scan, CodeQL and attestation have not completed a run yet. Runtime: the API/worker image contains no Docker CLI and the Docker socket is mounted only into the `executor` service, on a network only the API can reach; Postgres and Redis sit on an `internal` network with no published ports; in production only Caddy (80/443) is public and the balancer listens on loopback; nginx rate-limits per IP (30 req/s API, 20/min on `/auth`) in front of the application's own shared limiter, and overwrites `X-Forwarded-For` so clients cannot pick their own rate-limit identity. CD pins the deploy host's SSH key (no trust-on-first-use) and passes secrets through environment variables, not into shell text.
